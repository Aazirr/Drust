# Product

## Register

product

## Users

Small Rust teams and operation-focused players who want faster coordination during Oil Rig and related events.

They are usually mid-session, in voice chat, in Discord, or already in-game when they need the product. They do not want to stop and manage a complicated tool. They want the system to notice important triggers, surface the right information quickly, and reduce coordination overhead.

## Product Purpose

Drust is a Rust operations companion that connects Rust+, a web dashboard, and a Discord bot into one coordination loop.

Its purpose is to reduce manual tracking for high-tempo operations by:

- detecting or receiving important event signals
- turning those signals into actionable dashboard state
- pushing timely Discord alerts and countdowns
- keeping the team aligned with minimal manual input

Success looks like a team being able to react to an Oil Rig trigger quickly, see the current state in the dashboard, receive Discord timing cues, and coordinate without extra admin work.

## Brand Personality

Drust should feel tactical, fast, and reliable.

The voice should be direct, operational, and confidence-building. It should feel like a dependable squad tool rather than a flashy consumer app.

## Anti-references

Drust should not feel:

- very manual
- like it requires too much user input or repetitive setup during live play
- cluttered, noisy, or over-decorated
- playful when the user needs quick operational clarity

## Design Principles

- Automate first. Prefer system-detected state and defaults over manual user input.
- Surface the next important action. Show only what helps the team react and coordinate now.
- Keep coordination fast. Discord and the dashboard should reduce back-and-forth, not create more of it.
- Stay trustworthy. Time-sensitive alerts and operation state must feel dependable and easy to verify.
- Design for active play. The interface should support quick scanning while users are multitasking in-game and in voice.

## Accessibility & Inclusion

Target WCAG AA contrast and keyboard accessibility for the web dashboard.

Support reduced-motion preferences and avoid motion that blocks access to critical information. Prioritize legible type, clear status states, and fast visual scanning over decorative effects.
